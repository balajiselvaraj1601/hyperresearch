# Phase B2: Width sweep

Template: `../PHASE-TEMPLATE.md`. Procedure: `uv run hyperresearch run contract <vault_tag> 2` from `apps/hyperresearch`. Never the raw skill file.

**Purpose.** Answers: Is every atomic item covered by sources?
**Owner:** muse-worker
**Runs in:** one Muse exec or one OpenCode run for this phase, inside tmux `orch-hyperresearch-<slug>`.
**Starts from:** the previous phase gate, Pass or Conditional pass.
**Ends with:** a gate line in `dump/apps/hyperresearch/<slug>/output/runs/<vault_tag>/.work/gates.jsonl`.
**Tiers:** light and full
**Roles:** `fetcher` in non-overlapping waves; at most one `browser-fetcher`; `source-analyst` only for a long load-bearing source.

#### W. Work steps (numbered, each names what it produces)

1. Write the multi-lens search plan, then fetch with the CLI in waves.
   - Produces: vault notes tagged with the vault tag
   - In-step quality check: note count moving; no WebFetch
2. Write the coverage report. Thin is allowed. Uncovered is not.
   - Produces: temp/coverage-gaps.md
   - In-step quality check: no table row marked uncovered
3. On full, write the redundancy audit when any claims file exists. Drain the browser queue with one browser-fetcher or block on human-challenges and continue.
   - Produces: temp/redundancy-audit.md or an empty queue
   - In-step quality check: claims-*.json exists

The work steps above are the order. The words of the procedure are the rendered contract. Every role spawn ends with `uv run hyperresearch run contract <vault_tag> --role <role>` pasted verbatim, after the shim the contract names. Cite-checker gets no shim. Absolute paths only. Fetch with `uv run hyperresearch fetch`, never WebFetch.

#### O. Outputs and state contract

| Output | Ready means | Done means | Accepted means | Acceptor |

Done is not Accepted. Only Accepted releases the next phase. `run step` is bookkeeping after the gate, not the gate.

#### A. Abort, escalation, re-entry

- Abort trigger: more than half the fetchers fail, or the database lock survives two retries. Hold. Owner: muse-worker. Escalation destination: the registry `error` column and status `blocked`.
- Re-entry after Hold: fix this phase, run `gate_check.py` again, append a new gate line. Do not edit the old line.
- Database locked: sleep and retry at most twice. Do not delete the database, the WAL, or lock files.
- Do not write a stub artifact to make this gate pass.

#### H. Handoff

- State transition: `uv run hyperresearch run step <tag> 2 --status done -j` only after exit 0 or 2.
- Status line appended to `dump/apps/hyperresearch/<slug>/output/runs/<vault_tag>/.work/status.log`.
- Next phase is B3 on full, B10 on light. Its entry is this phase's accepted gate.
- Long results cross phases as file paths.
