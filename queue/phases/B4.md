# Phase B4: Loci analysis

Template: `../PHASE-TEMPLATE.md`. Procedure: `uv run hyperresearch run contract <vault_tag> 4` from `apps/hyperresearch`. Never the raw skill file.

Light tier does not run this phase. `gate_check.py` returns Pass with `skipped: true` and does not require these files.

**Purpose.** Answers: Which few questions deserve depth?
**Owner:** muse-worker
**Runs in:** one Muse exec or one OpenCode run for this phase, inside tmux `orch-hyperresearch-<slug>`.
**Starts from:** the previous phase gate, Pass or Conditional pass.
**Ends with:** a gate line in `dump/apps/hyperresearch/<slug>/output/runs/<vault_tag>/.work/gates.jsonl`.
**Tiers:** full
**Roles:** `loci-analyst`, profile count, one parallel batch.

#### A. Abort, escalation, re-entry

- Abort trigger: null source_budget. Hold and re-spawn the analyst once. Owner: muse-worker. Escalation destination: the registry `error` column and status `blocked`.
- Re-entry after Hold: fix this phase, run `gate_check.py` again, append a new gate line. Do not edit the old line.
- Database locked: sleep and retry at most twice. Do not delete the database, the WAL, or lock files.
- Do not write a stub artifact to make this gate pass.

#### H. Handoff

- State transition: `uv run hyperresearch run step <tag> 4 --status done -j` only after exit 0 or 2.
- Status line appended to `dump/apps/hyperresearch/<slug>/output/runs/<vault_tag>/.work/status.log`.
- Next phase is B5. Its entry is this phase's accepted gate.
- Long results cross phases as file paths.
