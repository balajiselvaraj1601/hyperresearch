# Phase B10: Triple draft

Template: `../PHASE-TEMPLATE.md`. Procedure: `uv run hyperresearch run contract <vault_tag> 10` from `apps/hyperresearch`. Never the raw skill file.

**Purpose.** Answers: What do independent angles conclude?
**Owner:** muse-worker
**Runs in:** one Muse exec or one OpenCode run for this phase, inside tmux `orch-hyperresearch-<slug>`.
**Starts from:** the previous phase gate, Pass or Conditional pass.
**Ends with:** a gate line in `dump/apps/hyperresearch/<slug>/output/runs/<vault_tag>/.work/gates.jsonl`.
**Tiers:** light and full
**Roles:** `draft-orchestrator`. Three angles on full, in one parallel batch. One on light, and that one writes the report. Full must not write the report in this phase.

#### E. Entry criteria (all mandatory ones must already be true)

| # | Criterion | Mandatory or advisory | Check (exact command or read) | Evidence |
|---|---|---|---|---|
| E0 | Run status is running, or blocked on verify, budget, or human-challenges | mandatory | `TAG=<tag> PHASE=B10 python3 apps/hyperresearch/queue/phases/gate_check.py` | `output/runs/<tag>/run.json` |

#### I. Inputs

| Input artifact | Exact path | Produced by phase | Frozen or live |
|---|---|---|---|
| digest or corpus | `temp/evidence-digest.md on full; vault notes on light` | B9 or B2 | frozen |

#### W. Work steps (numbered, each names what it produces)

1. On full, write three source lists and spawn three draft orchestrators.
   - Produces: temp/draft-a.md, draft-b.md, draft-c.md
   - In-step quality check: each file at least 500 characters; 1000 for argumentative
2. On light, one draft orchestrator writes the report.
   - Produces: output/reports/<tag>/final_report_<tag>.md
   - In-step quality check: required headings and citation style

The work steps above are the order. The words of the procedure are the rendered contract. Every role spawn ends with `uv run hyperresearch run contract <vault_tag> --role <role>` pasted verbatim, after the shim the contract names. Cite-checker gets no shim. Absolute paths only. Fetch with `uv run hyperresearch fetch`, never WebFetch.

#### O. Outputs and state contract

| Output | Ready means | Done means | Accepted means | Acceptor |
|---|---|---|---|---|
| drafts or the light report | angles assigned | three drafts on full; one report on light | gate Pass or Conditional pass | watcher |

Done is not Accepted. Only Accepted releases the next phase. `run step` is bookkeeping after the gate, not the gate.

#### A. Abort, escalation, re-entry

- Abort trigger: a missing draft. Re-spawn that angle once. Do not enter B11 with fewer than three drafts. Owner: muse-worker. Escalation destination: the registry `error` column and status `blocked`.
- Re-entry after Hold: fix this phase, run `gate_check.py` again, append a new gate line. Do not edit the old line.
- Database locked: sleep and retry at most twice. Do not delete the database, the WAL, or lock files.
- Do not write a stub artifact to make this gate pass.

#### H. Handoff

- State transition: `uv run hyperresearch run step <tag> 10 --status done -j` only after exit 0 or 2.
- Status line appended to `dump/apps/hyperresearch/<slug>/output/runs/<vault_tag>/.work/status.log`.
- Next phase is B11 on full, B15 on light. Its entry is this phase's accepted gate.
- Long results cross phases as file paths.
